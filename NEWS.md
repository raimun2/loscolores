# loscolores 0.2.0

The engine was rebuilt to match the web tool (<https://loscolores.raimundos.cl>).
Both engines now return exactly the same colours; `tests/testthat` checks this
against a fixture generated by the web engine (`node web/test/make_fixture.mjs`).

## Fixes

* **Luminance ladder.** The old minimum gap of 0.15 could not be met with 7
  levels (the maximum possible is about 0.123), and its fallback ignored the
  anchor, so most palettes ended with core colours 0.001 to 0.05 apart in L.
  The satellites are now split above and below the anchor to maximise the
  minimum gap (about 0.10 to 0.16 across the bundled palettes).
* **Poles.** Only neutral colours (chroma < 0.04) can become a pole. Before, a
  navy anchor became the black pole and a yellow became a grey white pole.
  Poles are always neutral greys, including the defaults.
* **Anchor.** Its exact hex and L are kept. Before, a very light or dark anchor
  was clamped. If the anchor is too close to a pole, the pole moves outward.
* **Gamut mapping** keeps L and hue and reduces only chroma. Before, per-channel
  clipping shifted lightness.
* **Distillation** is deterministic and keeps real input colours (medoids).
  Before, `kmeans()` had no seed and returned averaged colours.

## Changes

* Expansion places new hues as far as possible from the existing ones.
* Divergent palettes use the complement at the same lightness and chroma as the
  base colour (before: 0.4 darker).
* Categorical palettes with more than 5 colours interpolate linearly in OKLab.
* New `pivot` argument in `set_loscolores()` and `loscolores_system()`.
* `print()` shows the log of every decision; `system_report()` shows the full
  ladder and minimum gap.
* `get_expansion_params()` was removed (internal). `farver` is no longer needed.
